# 05 — IA: 3D Gaussian Splatting y modelos

[COMPROBADO: inspección de `pylib/terra_3dgs/`, 2026-10-30]

## Hallazgos
- Python 3.12. El ejecutable `terra_3dgs.exe` es un lanzador propio (sin PyInstaller/
  Nuitka/py2exe); el bytecode Python de DJI **no está presente como `.pyc` legible**.
- El cómputo del 3DGS vive en una **extensión CUDA C++**: `terra_gs/csrc.pyd` (módulo
  `csrc`, 13 MB, lleno de kernels CUDA SASS/PTX) y `knn_cuda/knn.pyd` (KNN CUDA).
- Hay un **modelo de IA cifrado**: `model/ai_fm.p0/p1/p2.enc` (~940 MB). "fm" = foundation
  model (lo usa `terra_fm.exe`). Cifrado como las .db propietarias.

## Implicación para terra-oss
- No hace falta el código ni el modelo de DJI. El 3DGS se implementa con **gsplat** o el
  3DGS de Inria (libres). La calidad se iguala con el pipeline estándar.
- Specar los kernels de `csrc.pyd` queda para Fase 6 (Ghidra) y solo si aporta algo que
  gsplat no dé. El modelo cifrado queda fuera de alcance (no se descifra).
- `3dgs_report.json` (visto en TerraSDK) es el formato de salida del proceso 3DGS → sí se
  documentará su esquema cuando haya muestra o código que lo escriba.
